# Datasets on the Hugging Face Hub

Datasets are not committed to git (`datasets/` is gitignored). They live on the Hub; this file says where and how
each one was made.

## `zabsy/pioneer_8dof_peg_insert_synthetic` (private)

Synthetic peg-insertion demos, 8dof left arm, MuJoCo `peg_insert` scene (2 mm clearance a side), made by the
simulated operator in `src/teleop/pioneer_leader_arm_teleop/synthetic/`. Base demos for the RL-token (RLT) experiments.

- Format: LeRobot v3, 25 fps, `pioneer_8dof_dataset_schema.yaml` (8-value state and action, `ego` and `wrist_left`
  cameras at 640x480). `meta/synthetic_takes.jsonl` logs each take's seed and operator style.
- Seeds: drawn from 0..499, in order. Evaluate on seeds it does not use (e.g. `evaluate.py --seed 1000`).
- Takes kept: successful and at most 30 s long. Of seeds 0..499, 298 succeed (60%, median take 13.5 s) and 280 of
  those are 30 s or shorter. The long ones are many-retry takes (one is 163 s); dropping them keeps the demos clean,
  and the recorder buffers a whole take in RAM, so a 2-minute take runs a 16 GB machine out of memory.

Generated by probing seeds without cameras (fast), then recording the kept ones one at a time (a rerun with the same
`--dataset_root` skips seeds already saved):

```bash
MUJOCO_GL=egl python synthetic/synthetic_teleop.py --scene peg_insert --num_episodes 400 --max_tries 500 --seed 0  # probe
# for each kept seed s (ok, <= 30 s), with n = takes already saved + 1:
MUJOCO_GL=egl python synthetic/synthetic_teleop.py --scene peg_insert --record --seed $s --max_tries 1 \
  --num_episodes $n --dataset_root <out>/peg_ds
```

Rendering is the slow part: on a CPU-only box (4 cores, software OpenGL) a take costs about 15 minutes, mostly the
shadow passes of the workcell's 7 lights; on a GPU it is seconds.

Load it:

```python
from lerobot.datasets.lerobot_dataset import LeRobotDataset
ds = LeRobotDataset("zabsy/pioneer_8dof_peg_insert_synthetic")
```
